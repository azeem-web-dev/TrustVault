# Login timing measurement

Generated by `npm run measure:timing` (apps/api/test/timing/login-timing.measure.ts) on 2026-11-01T12:38:47.538Z.

Question: can someone tell from the response time of a failed login whether the email has an account? 250 failed logins of each kind, interleaved in random order, through the full HTTP stack with production Argon2id (64 MiB, 3 passes). Failed-login floor: 450 ms. Machine: AMD Ryzen 5 5500                               , win32.

| Case | median ms | mean ms | sd ms | p10 ms | p90 ms |
|---|---|---|---|---|---|
| unknown | 459.7 | 460.0 | 4.2 | 454.4 | 465.9 |
| wrong | 459.9 | 460.2 | 4.9 | 453.8 | 467.3 |
| locked | 459.2 | 459.4 | 4.4 | 453.5 | 465.5 |

An attacker's best single threshold, fitted on half the samples and tested on the other half (50% = coin toss):

- unknown email vs real account, wrong password: **52.8%** (median difference 0.3 ms)
- unknown email vs locked account: **55.2%** (median difference -0.5 ms)

Every failed login, whatever the reason, also gets the same response body and status (401, "Invalid email or password"), and is rate limited per account and per IP, which caps how many samples a real attacker could collect.

The padding hides small differences; the code paths are also equal without it. With the padding off (`TIMING_FLOOR_MS=0`): [LOGIN_TIMING_floor0.md](LOGIN_TIMING_floor0.md).
