# THREATS.md

How I believe TrustVault could be broken, what I did about each, how I know it holds, and what I knowingly accepted. Statuses:

- **done**: defended, and the test named in the right-hand column fails if the defence is removed. `node tools/mutation-check.mjs` removes the main checks one by one to prove it; see [docs/MUTATION_REPORT.md](docs/MUTATION_REPORT.md).
- **accepted**: a known weakness I chose to leave, with the reason.
- **partial**: some defence, with the gap stated.

Test files live in `apps/api/test/`. "live" means checked by hand against https://vault.rayyanazeem.cloud.

## The model in one paragraph

Every document request passes **two independent locks**. Lock 1 is `decide()` in `apps/api/src/documents/access.ts`, a pure function over raw facts that denies by default. Lock 2 is Postgres **row-level security**, driven by `tv_doc_level()`, written separately in SQL. The API connects as a role that owns nothing, so RLS always applies, and it sets `app.user_id` per transaction. Grants and group membership are read live on every request; nothing is cached. The audit log is written by the database itself: hash-chained by a trigger, append-only by both privileges and triggers, signed every minute there are new events by a separate key service, and copied off the server by an outside witness that the server cannot write to.

## V. View-only, copies and leaks

Added 2026-11-03. **The honest limit first:** anyone who can see a page can photograph it. Nothing in software stops a second camera. What view-only does is keep the original file off people's devices, make Android refuse screenshots and screen recording, and print the viewer's name, the time and a trace code on every page, so a leaked picture leads back to one person and one moment. Everything below is either a lock on the original bytes or one of those three things.

## Not built, on purpose

- **Anonymous share links.** Every outsider is a named EXTERNAL account with an expiry, so there is never a link that works for whoever holds it.
- **End-to-end encryption.** It would stop the server from validating uploads, searching and auditing. The threat it addresses (a fully compromised server) is accepted above (I6, L8).
- **Previews of Word, Excel and PowerPoint files.** Drawing them needs LibreOffice on the server, a large attack surface. PDFs, images and text are drawn for view-only access since 2026-11-03 (V2, V8); Office files can only be downloaded.
- **Folder inheritance.** Folders organise and never grant. "Given a folder to see one file, can now see forty" is the first problem in the brief.
